# 官方 Codex A/B：GPT-5.6-sol vs Hy4-preview

测试日期：2026-08-30（北京时间）  
运行器：[`scripts/codex_ab_benchmark.py`](../../scripts/codex_ab_benchmark.py)  
原始记录：[`codex-ab-all.json`](2026-08-30-codex-ab-all.json)（3 轮合计 36 次调用）

## 测试方法

两模型均通过官方 Codex CLI 的 `codex exec --json` 调用，使用相同提示词和只读沙箱。GPT-5.6-sol 使用本机已配置的 Codex provider；Hy4-preview 使用腾讯 MaaS `/v1/responses`，腾讯 key 仅从 `configs/secrets.env.local` 读取，不写入结果文件。

测试包含 6 项端到端任务，使用修订后的唯一答案逻辑题；完整有效测试重复 3 轮，共 36 次请求（每个模型 18 次）：

| 项目 | 权重 | 判定方式 |
|---|---:|---|
| 约束逻辑 | 20 | 唯一正确选项 `C` |
| 多步数学 | 15 | 最终整数 `9` |
| 代码契约 | 20 | 提取模型代码并实际执行，stdout 为 `[0, 1]` |
| 严格格式约束 | 15 | 三行内容和顺序完全符合要求 |
| 严格 JSON | 15 | JSON 可解析且字段值正确 |
| 长上下文定位 | 15 | 180 条记录中定位 `ZX-4179` |
| **总计** | **100** |  |

服务错误、认证错误或超时与能力分开记录；有效 3 轮没有此类失败。Codex 对 Hy4 有一条元数据警告（模型未在本地元数据表登记），不影响请求完成，也不计入能力扣分。

## 失分复核

逻辑题的条件是 `A 在 B 前、B 在 C 前、D 和 E 无约束`，因此必然在 B 后的是 `C`。修订后的 3 轮中两模型均 3/3 正确。此前首轮使用过一条有歧义的逻辑题，已从有效统计中剔除。

Hy4 唯一失分是第 2 轮严格 JSON：返回 `{"answer":null,"steps":[],"confidence":0.0}`，HTTP 请求正常完成，但字段值不符合题目。这不是服务错误或截断。

代码项不能只用文本是否包含 `[0, 1]` 判断。每轮两模型生成的代码均已在隔离 Python 进程执行，退出码为 0，标准输出均为 `[0, 1]`，所以代码项两边均得满分。

## 结论与限制

在 6 个任务、3 轮重复的官方 Codex 端到端测试中，GPT-5.6-sol 为 18/18（100/100），Hy4-preview 为 17/18（按权重平均 95/100）。差异仅来自一次严格 JSON 失败；数学、逻辑、代码执行、格式遵循和长上下文定位两边均为 3/3。Codex 编排后本轮没有出现 `finish_reason=length` 或空最终答案，说明它确实改善了此前直连测试中的交付问题，但不能据此证明模型在所有长推理任务上等价。

这不是独立第三方排行榜。样本只有 6 类任务，仍应扩展到更多题目和不同难度，并报告置信区间、token 成本和服务错误率后再下长期结论。
